# Bubbles — Telegram-уведомления (отдельный сервис)

В отличие от `supabase/functions/` (это Supabase Edge Functions,
живут внутри Supabase), этот бот — обычный Python-сервис
(FastAPI + python-telegram-bot). Он принимает два вида входящих
запросов на один и тот же процесс:

1. `/telegram/webhook` — Telegram сам стучится сюда при каждом
   сообщении боту (`/start`, `/link`, `/settings`, `/status`,
   `/unlink`).
2. `/bubbles/webhook` — сюда стучатся Database Webhooks Supabase при
   появлении новых уведомлений/сообщений, а бот пересылает их в
   Telegram.

Оба — обычные HTTP-запросы, поэтому сервис можно деплоить на любой
обычный веб-хостинг (в том числе бесплатный тариф Render) — ему не
нужен постоянно работающий процесс, который «висит и опрашивает»
Telegram (long polling). Это важно: именно long polling раньше
усыплялся хостингом при простое — см. ниже.

Таблицы (`telegram_links`, `telegram_link_tokens`,
`notification_settings`) и функция `create_telegram_link_token()`
находятся в общем `supabase.sql` проекта, не здесь — прогони его как
обычно.

## 1. Создай бота в Telegram

1. Открой [@BotFather](https://t.me/BotFather) → `/newbot` → задай имя
   и юзернейм (должен заканчиваться на `bot`).
2. Сохрани токен вида `123456789:AA...`.
3. Впиши юзернейм бота (без `@`) в `js/telegram-config.js` в основном
   проекте Bubbles — это то, что видит пользователь в интерфейсе
   ("Откройте @ИМЯ_БОТА").

## 2. Задай переменные окружения

Скопируй `.env.example` в `.env` (или впиши то же самое в Environment
своего хостинга — см. шаг 3) и заполни:

```
TG_BOT_TOKEN=<токен от BotFather>
SUPABASE_URL=https://<project-ref>.supabase.co
SUPABASE_SERVICE_ROLE_KEY=<service_role ключ из Supabase → Settings → API>
BUBBLES_URL=https://<адрес твоего сайта Bubbles>
BUBBLES_WEBHOOK_SECRET=<придумай длинную случайную строку>
TELEGRAM_WEBHOOK_SECRET=<придумай ДРУГУЮ длинную случайную строку>
PUBLIC_URL=https://<публичный адрес ЭТОГО сервиса — узнаешь после первого деплоя>
PORT=8080
LOG_LEVEL=INFO
```

Два разных секрета отвечают за разные направления:
- `BUBBLES_WEBHOOK_SECRET` — проверяет, что `/bubbles/webhook` дёргает
  именно твой Supabase (см. шаг 4).
- `TELEGRAM_WEBHOOK_SECRET` — проверяет, что `/telegram/webhook`
  дёргает именно Telegram, а не кто попало, кто узнал URL. Технически
  необязателен (если оставить пустым — проверка просто отключается),
  но рекомендуется.

`PUBLIC_URL` — это адрес самого бота (не Bubbles и не Supabase). Его
не узнать заранее — сначала задеплой сервис (шаг 3) с остальными
переменными, посмотри, какой адрес выдал хостинг, впиши его в
`PUBLIC_URL` и передеплой ещё раз (или просто перезапусти — этого
достаточно, если хостинг подхватывает переменные без пересборки).
Именно по этой переменной бот при старте сам регистрирует себя как
webhook в Telegram — вручную вызывать `setWebhook` не нужно.

⚠️ `SUPABASE_SERVICE_ROLE_KEY` даёт полный доступ к базе в обход RLS.
Это нормально — именно ради этого сервис и существует отдельно от
браузера — но храни его только в переменных окружения хостинга,
никогда не коммить `.env` и никогда не вставляй этот ключ ни в один
файл фронтенда.

## 3. Задеплой сервис

Подойдёт любой хостинг, который умеет Dockerfile: Render (обычный
**Web Service**, бесплатного тарифа достаточно — см. примечание про
сон ниже), Railway, Fly.io, свой сервер. На Render: New → Web Service
→ укажи этот репозиторий → Root Directory: `telegram-bot` → Environment:
Docker → задай переменные из шага 2 (кроме `PUBLIC_URL` — его пока не
знаешь) → Deploy.

После первого деплоя Render покажет адрес вида
`https://bubbles-telegram-bot.onrender.com` — впиши его в переменную
`PUBLIC_URL` и сохрани (сервис перезапустится сам). Локально/на своём
сервере — то же самое через обычный Docker:

```
docker build -t bubbles-telegram-bot ./telegram-bot
docker run -d --env-file ./telegram-bot/.env -p 8080:8080 bubbles-telegram-bot
```

Проверь, что сервис жив:

```
curl https://<твой-домен-бота>/health
# {"ok":true,"service":"bubbles-telegram-notifications"}
```

И что вебхук зарегистрировался (это можно проверить, даже если сервис
сейчас спит — не поднимает его):

```
curl "https://api.telegram.org/bot<TG_BOT_TOKEN>/getWebhookInfo"
# в ответе "url" должен быть https://<твой-домен-бота>/telegram/webhook
```

### Про бесплатный тариф Render и «сон»

Бесплатный Web Service на Render усыпляется примерно через 15 минут
без входящих запросов и просыпается по следующему запросу — это
нормально для этой архитектуры (в отличие от long polling, где сон
означал полную остановку бота). Единственное следствие: **первое**
сообщение после долгого простоя придёт с задержкой ~20–40 секунд,
пока Render поднимает инстанс, — Telegram просто подождёт ответа и не
потеряет сообщение. Все следующие сообщения, пока сервис не заснул
снова, приходят быстро. Если такая задержка неприемлема — платный
тариф Render (или Railway/Fly.io с always-on) полностью её убирает.

## 4. Подключи два Database Webhook в Supabase

Dashboard → **Database** → **Webhooks** → **Create a new hook**,
дважды — оба указывают на один и тот же URL:

**Хук №1 — уведомления (лайки/комменты/заявки в друзья/стена/питомец):**
- Table: `bubbles_notifications`
- Events: `Insert`
- Type: **HTTP Request**
- URL: `https://<твой-домен-бота>/bubbles/webhook`
- HTTP Headers: `X-Bubbles-Webhook-Secret: <тот же секрет, что в BUBBLES_WEBHOOK_SECRET>`

**Хук №2 — сообщения:**
- Table: `messages`
- Events: `Insert`
- Type: **HTTP Request**
- URL: тот же `https://<твой-домен-бота>/bubbles/webhook`
- HTTP Headers: тот же `X-Bubbles-Webhook-Secret`

Без правильного заголовка сервис отвечает `401` и ничего не
пересылает — это и есть проверка, что запрос действительно пришёл от
твоего Supabase, а не от кого попало, кто узнал URL. (Если сервис в
этот момент спал — Supabase дождётся ответа так же, как и Telegram, и
разбудит его этим же запросом.)

## 5. Проверка полного потока

1. Bubbles → Настройки профиля → **🔔 Telegram-уведомления** →
   «Подключить Telegram» — появится код вида `BUB-7K4Q9P`.
2. Либо нажми «Открыть бота» (сработает автоматически, код передастся
   через `/start`), либо вручную отправь боту `/link BUB-7K4Q9P`.
3. Бот ответит `✅ Telegram успешно подключён к вашему аккаунту
   Bubbles!`, а страница настроек Bubbles сама обновится на
   «🟢 Telegram подключён» в течение нескольких секунд.
4. `/settings` — переключи что-нибудь, попроси кого-нибудь лайкнуть
   пост или написать сообщение — должно прийти уведомление
   (или не прийти, если соответствующий тумблер выключен).
5. `/unlink` — должно прийти `🔕 Telegram отключён от Bubbles`, а
   Bubbles вернётся к состоянию «не подключено» после обновления.

## Если что-то не работает

- **Код не находится** — убедись, что обновлённый `supabase.sql`
  прогнан (нужны таблицы `telegram_link_tokens`/`telegram_links`/
  `notification_settings`), и что копируешь код без лишних пробелов.
- **"Код истёк"** — коды живут 10 минут, сгенерируй новый в Bubbles.
- **Бот вообще не отвечает** — проверь `getWebhookInfo` (см. шаг 3):
  если `url` пустой — `PUBLIC_URL` не задан или сервис ни разу не
  стартовал с ним; если там есть `last_error_message` — читай его,
  обычно это неверный `TELEGRAM_WEBHOOK_SECRET` или сервис недоступен
  снаружи. Логи сервиса на хостинге тоже покажут, доходят ли вообще
  запросы до `/telegram/webhook`.
- **Первое сообщение после паузы приходит с задержкой** — ожидаемо на
  бесплатном Render, см. раздел про сон выше. Не баг.
- **Бот отвечает, но уведомления о лайках/сообщениях не приходят** —
  проверь оба Database Webhook: правильный ли URL, правильный ли
  заголовок `X-Bubbles-Webhook-Secret`, и нет ли `401`/`500` в логах
  сервиса при лайке/сообщении.
- **Уже подключён другой Telegram** — просто пришли `/link НОВЫЙ_КОД`
  (или открой бота по новой ссылке) из другого Telegram-аккаунта:
  старая связь автоматически заменяется новой.
- **Одно и то же уведомление пришло дважды** — не должно происходить:
  каждая строка помечается `telegram_sent_at` сразу после отправки, и
  сервис перепроверяет это поле заново из базы перед каждой отправкой
  (а не доверяет содержимому вебхука), так что повтор вебхука не
  дублирует сообщение. Если всё же случилось — это стоит расследовать
  как баг, а не игнорировать.
